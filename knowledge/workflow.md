# Методика работы со стратегией

## Исследование

Классифицируй записи реестра как `brief_fact` для данных условного мира брифа, `public_fact` для открытых источников, `assumption`, `forecast` и `synthetic`. В новых кейсах `brief_fact` также подходит для проверяемых сведений из предоставленного документа. Факт об одном операторе применим только к нему. Интервью помогают восстановить поведение. Для оценки частоты нужна выборка или журнал с понятным знаменателем. Модельный респондент генерирует гипотезы.

Для каждого вопроса укажи, какое решение зависит от ответа, какая запись или наблюдение его прояснит и что делать до получения данных. Не делай повторный веб-поиск без нового вопроса. Используй Web в Codex только для разрешённых публичных источников, а сохранённые выдержки — для офлайн-проверки. Для локального входа используй `python strategist.py inspect <файл>`. PDF требует опционального `pypdf`. В демо приложена текстовая копия для автономного чтения.

## Стратегия и проверка

Описывай одну клиентскую ситуацию, сравнимые альтернативы, причинный механизм, доступный охват, стоимость и обратимость. Согласуй обещание с реальными правами и операцией. Определи для метрики единицу, период, числитель, знаменатель и обработку пропусков. Зафиксируй базу сравнения, условия включения, порог практически значимого эффекта и критерии остановки. При групповом влиянии единица распределения должна охватывать всю группу.

Для расходов и прибыли используй одну базу и период, учитывай только дополнительные объёмы, один раз вычитай прямые расходы, отдельно показывай вложения и срок окупаемости. В новых кейсах выбери подходящий расчёт и сохраняй исходные таблицы, код и дневник допущений.

## Проверка и пересмотр

Локальный источник указывай путём относительно кейса. Для файлов проекта используй префикс `repo:`. Контрольная точка сохраняет SHA-256 каждого процитированного локального источника. `status` называет затронутый артефакт и ID, `verify` возвращает ошибку при изменении или утрате файла. Для смены основания внеси новую версию отдельным файлом. URL сохраняется как ссылка. Для проверки содержимого внешней страницы приложи датированную локальную копию и укажи URL в локаторе.

Файл обновления и его локальное основание проверяются с момента регистрации, в том числе пока отчёт о пересмотре остаётся черновиком.

В учебном MCP перед началом второй сессии создаётся снимок входной таблицы. Расчёт и регистрация обновления используют этот снимок. Если его изменили после подготовки, пересмотр приостанавливается до восстановления исходного файла.

Новое основание дополняет реестр. Существующие записи и их содержимое сохраняются.

Проверь, что рекомендации объясняются источниками, допущения помечены, обещание выполнимо и пороги заданы заранее. Передавая решение руководителю, укажи объём, владельца, срок, доказательства и следующие возможные действия. После изменения основания пересмотри выводы, на которые оно влияло. Автоматический поиск ссылок подсказывает, где смотреть. Связи и смысл проверяет агент. Новая версия должна явно указать, какое прежнее решение пересмотрено, почему и что делать дальше.

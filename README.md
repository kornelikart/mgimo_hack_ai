# Стратег Фабрики продуктов

ИИ-агент для руководителя цифрового продукта. В Codex он ведёт кейс от размытого запроса до рекомендации, продуктовой и коммуникационной стратегии. Сохраняет основания и возвращается к решению при новых данных. Статус хранится в проекте и доступен в новом чате.

## Первый запуск

Для работы нужен Python 3.11+ и доступ к Codex для рассуждений агента. Скрипты, источник-таблица и офлайн-повтор используют стандартную библиотеку Python. Своих API-ключей проект не требует. Для самостоятельного чтения новых PDF можно установить `python -m pip install -r requirements-pdf.txt`. В демонстрации приложена текстовая копия. Веб-проверка использует доступный в Codex поиск и открытые сайты.

1. Откройте папку проекта в Codex. Для нового кейса отправьте:

   > Используй AGENTS.md. Начни новый кейс. Нужно решить, стоит ли тестировать напоминание об оплате второго номера для роутера. Сначала выясни, какое решение нужно и какие данные его изменят.

2. Дайте агенту ссылки и локальные материалы. Агент сам выбирает следующий исследовательский шаг, использует инструменты и завершает каждый этап после проверки. При существенном выборе он покажет варианты и попросит решение. Если нужно прервать работу, попросите сохранить черновик и указать следующий шаг.
3. В новом чате отправьте «Продолжи кейс <id> по AGENTS.md. Начни со статуса и покажи следующее существенное действие». Прежний чат для продолжения не нужен.

### Проверяемый повтор

Из корня проекта выполните:

```text
python economics.py
python demo.py prepare
python demo.py status
python demo.py review
```

`prepare` воспроизводит четыре готовых артефакта и условный выбор руководителя. `review` в отдельном процессе читает сохранённый статус, подаёт синтетическое обновление, находит зависимые места и фиксирует новое решение. Эта последовательность проверяет механику хранилища и расчётов. Готовые тексты предоставлены для повторяемости, запуск модели осуществляется в Codex. Рабочая копия находится в `dist/demo-cases/`; для отдельного повтора передайте одинаковый `--work <папка>` всем трём командам.

### Повтор с агентом в Codex

В новом чате попросите:

> Следуй AGENTS.md. Прогони бриф из cases/family-internet/inputs в новом кейсе family-live. Используй brief.pdf или brief.txt, baseline.csv, rollout.csv и public-sources.md. Файл timing-update.json понадобится позже. Проведи исследование и сравни варианты. Укажи, какое решение нужно от меня до пилота.

Зафиксируйте выбранное действие. Во втором чате попросите:

> Продолжи family-live по сохранённому состоянию. Я передаю cases/family-internet/inputs/timing-update.json как учебное свидетельство. Свяжи его со своими основаниями, покажи затронутые выводы и подготовь пересмотр.

### Воспроизведение двух сессий и контрольного сравнения

Понадобится установленный Codex CLI с активным входом и доступом к модели. Команды запускают независимые сессии. Локальный MCP работает только с указанным учебным кейсом и получает разрешения через автоматическое рассмотрение Codex. Первая сессия видит исходные материалы, вторая получает замер и читает сохранённое состояние.

```text
python live_run.py prepare
python strategist.py --cases-dir dist/live-router/cases decide router-live --simulated --decision "Проверить готовность" --owner "Руководитель продукта" --metric "Доля событий за 24 часа" --revisit "После нового замера"
python live_run.py review
python live_run.py baseline-prepare
python live_run.py baseline-review
python benchmark.py
```

Для нового эксперимента укажите один отдельный `--work` во всех вызовах `live_run.py` и `benchmark.py`, а в `--cases-dir` — подпапку `cases` этого каталога. Для явного выбора той же модели в обеих ветках передайте одинаковый `--model`. Подробное движение кейса и время из проверенного прогона лежат в `cases/router-payment/results/`.

После прерывания повторите команду этапа с той же папкой `--work`. Раннер продолжит с первой незавершённой контрольной точки. Предыдущий журнал сохранится в подпапке `attempts/`. В отчёте сравнения указано время завершившихся запусков.

### Проверка источников и пилота

`strategist.py status` показывает затронутый артефакт, ID и путь, если процитированный локальный файл изменился или пропал. `verify` возвращает ошибку в обоих случаях. Это действует и для зарегистрированных обновлений, по которым ещё готовится пересмотр. Старые контрольные точки проверяют наличие явно указанных файлов. Исторические текстовые пометки остаются в реестре. Для проверки содержимого нужна сохранённая контрольная сумма. Внешние страницы проверяются по локальным датированным копиям, если они приложены.

Для семейного кейса `python economics.py` планирует 2 600 семей при 12% в контроле и 8% в плановом сценарии. Совместное статистическое правило требует снижения минимум на 3 п.п. и нижней границы 95% интервала выше нуля. Проверка на учебных счётчиках запускается командой `python economics.py --results 1300 156 1300 117`. Финансы и эксплуатация проверяются перед расширением отдельно.

При недоборе в любой группе результат отмечается как неопределённый. Доверительный интервал разности долей вычисляется по гибридному методу Ньюкомба на основе интервалов Уилсона. [Метод расчёта](https://pubmed.ncbi.nlm.nih.gov/9595617/)

Регрессионные проверки запускаются командой `python -m unittest discover -s tests`.

## Устройство репозитория

| Файл | Для чего |
|---|---|
| `AGENTS.md` и `knowledge/workflow.md` | Правила, последовательность действий и исследовательская методика |
| `strategist.py` | Статус, контрольные точки с хешами, проверка ссылок, решение и поиск затронутых мест |
| `economics.py` | Проверка входной таблицы и воспроизводимый расчёт по демонстрационному брифу |
| `demo.py` | Офлайн-повтор по готовым артефактам с раздельными запусками |
| `live_mcp.py`, `live_run.py`, `benchmark.py` | Учебные инструменты, независимые сессии Codex и измеренное сравнение с обычным чатом |
| `cases/family-internet/` | Данные, результаты, журнал допущений и материалы кейса |

Ключевой интерфейс — чат. CLI хранит состояние и валидирует структуру. Семантическую проверку источников и выводов выполняет агент. PDF с изображениями без текстового слоя потребует отдельно предоставленной расшифровки. Сайты считываются через доступные средства Codex. Разнородные таблицы предпочтительно подавать как CSV или TSV. Утверждённые контрольные точки защищены проверкой целостности, пересмотр сохраняется отдельной версией. Запуск, расширение и расходы утверждает человек.
